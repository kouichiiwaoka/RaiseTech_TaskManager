# Task Board プロトタイプ

画面設計書 S-01〜S-05 を操作して確認するための、HTML・CSS・JavaScriptのみのローカルデモです。外部ライブラリ・外部フォント・通信・バックエンド・DB・課金サービスは使用しません。

## 開き方

`index.html` をChromeで開いてください。インストールやビルドは不要です。

ファイルを直接開いた環境で保存が制限される場合は、リポジトリのルートで以下を実行し、`http://127.0.0.1:8000/prototype/` を開いてください。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

終了はサーバーを実行しているターミナルで Ctrl+C。外部公開はしません。

## 確認できる内容

- 未着手・作業中・完了の3列と、優先度・期限を示すカード
- タスク追加 → ボード、詳細 → 編集 → 詳細、詳細 → 削除確認 → ボード
- タイトル必須の検証、複数行説明、期限なし、編集キャンセル
- ドラッグ＆ドロップで列間の移動、列内と列間の指定位置への並べ替え
- 各列で独立した優先度・期限の昇順／降順ソート（列ごとに4ボタン）
- 削除確認のキャンセル、確認省略チェックと設定保持
- localStorageでの保存・再読み込み後の復元
- デモメニューで空のボード、サンプルへの復帰、保存失敗・取得失敗を確認
- モーダルのフォーカス制御、Tab移動、Escapeによるキャンセル

## 合意した画面仕様（2026年11月15日）

- 白と淡いグレー、グリーンのアクセントを使用。優先度は色と文字で表示。
- PCを中心とし、狭い画面ではボードを横スクロール。
- 新規カードは「未着手」の末尾に追加し、ソート条件があれば適用する。
- 優先度の昇順は低→中→高、降順は高→中→低。期限の昇順は近い順、降順は遠い順。期限なしは常に最後、同順位は直前の順序を保持。
- ボード全体の表示順欄と手動順ボタンは設けない。各列の条件と並び順を保存する。
- ソート中もドラッグ可能。実際に移動したときは移動元・移動先の条件を解除し、配置を優先する。他の列の条件は維持する。
- 旧デモの全体ソート設定は各列の条件へ自動移行。旧手動順は条件未選択として読み込む。
- 編集保存・キャンセルは詳細へ戻り、削除確認のキャンセルも詳細へ戻る。
- 保存成功後に画面へ反映。失敗時は確定せず、フォーム入力は維持。移動失敗では元の位置を維持。
- デモメニュー内の削除確認の再有効化は検証用。本番で提供するかは未決定。
- サンプルの期限は初期生成時点のローカル日付を基準とする。
- 全タスクが空でも列を維持。空の列へドラッグ＆ドロップ可能。

## 保存と制限

保存先キーは `raisetech-taskboard-prototype-v1`。サンプルへの復帰・空のボード操作は、このデモ専用キーだけを置き換えます。実在の個人情報や秘密情報は入力しないでください。

この保存は本番要件のDB保存を代替する仮実装です。ブラウザ・プロファイル・オリジンごとに独立し、別端末と共有しません。file URLでの保存挙動はブラウザに依存します。Chromeの最近のバージョンを想定します。

取得できない保存データは自動で上書きせず、再取得か、明示的なデモ初期化を案内します。保存失敗デモは次の保存1回のみ失敗させます。バックエンド・通信エラーの表示も同じUIで疑似確認する想定です。

複数タブの同時編集・競合解決、スマートフォンのタッチドラッグ、キーボードによるカード移動は対象外です。このデモの実装技術は画面確認専用です。実アプリはReact / TypeScript / Vite / Tailwind CSS、Java / Spring Boot / Gradle、PostgreSQLで構成します。採用技術の詳細は[技術構成書](../技術構成書.md)を参照してください。

## レビュー観点

1. ボードとカードの情報量・余白・文字サイズは適切か。
2. 追加ボタン、詳細からの編集・削除の導線は自然か。
3. モーダルの入力項目、ボタン配置、キャンセルの戻り先は適切か。
4. 移動先と挿入位置が分かりやすいか。
5. 各列での優先度・期限の昇降順とドラッグの使い分けは自然か。
6. 空状態や入力エラー・保存失敗が分かりやすいか。
