# Task Board フロントエンド

既存のタスクREAD APIからデータを取得し、未着手・作業中・完了の3列に表示するReactアプリです。合意済みの[プロトタイプ](../prototype/index.html)のレイアウト・配色を引き継いでいます。

## 必要な環境

- Node.js: `^22.22.2 || ^24.15.0 || >=26.0.0`（使用するテストツールを含む依存関係の要件）
- 検証環境: Node.js 26.7.0 / npm 11.19.0。`.node-version`にも記載しています。
- PostgreSQLとSpring Bootの起動環境は[バックエンドREADME](../backend/README.md)を参照してください。

## 使用バージョン

React / React DOMは19.3.1、TypeScriptは6.0.3に固定しています。2026年11月17日に確認したTypeScript最新安定版は7.0.2ですが、最新typescript-eslint 8.72.2も対応範囲が`>=4.8.4 <6.1.0`のため、今回は更新しません。ほかの技術も含めた採用・維持理由と更新方針は[技術構成書](../技術構成書.md)の1.1・1.2節を参照してください。

## ローカルで起動する

1. 元のプロジェクトディレクトリで、既存のREADMEに従ってDBとバックエンドを起動してください。バックエンドは通常 `http://127.0.0.1:8080` です。フロントエンドには `.env` やDBパスワードは不要です。
2. 元のプロジェクトディレクトリの `frontend/` で実行します。追加ワークツリーは使用しません。

```sh
npm ci --ignore-scripts --no-audit --no-fund
TASK_API_TARGET=http://127.0.0.1:8080 npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

3. Chromeで `http://127.0.0.1:5173/` を開きます。

`npm ci`は依存関係をlockファイルどおりにそろえるコマンドです。すでに必要な依存関係がある環境では再実行は不要です。起動中の開発サーバーはCtrl+Cで停止します。5173が使用中の場合は自動で別ポートに切り替えずエラーになります。

標準ポートはフロント5173・バックエンド8080・DB5432に固定します。競合時は別ポートへ変更せず、起動元を確認して競合サービスを通常停止してから起動します。同じプロジェクトが正常起動済みなら再利用します。詳しくは[統一起動スキル](../skills/start-frontend-backend/SKILL.md)を参照してください。

DBが空ならボードも空です。必要ならバックエンドREADMEのローカル専用の架空データ投入手順を使用してください。通常起動ではサンプルを自動投入しません。

## 操作

- 初回表示は全件取得です。
- ボード下の「タスクを検索」を開き、「タイトルを検索」と「ステータス」を入力します。検索ボタンまたはEnterで検索します。入力途中では検索しません。
- タイトルは部分一致で検索し、大文字小文字を区別しません。説明文は検索対象外です。
- ステータスとタイトルを両方指定すると両条件に一致するタスクを表示します。
- クリアで入力と適用条件をリセットし、全件を取得します。
- 件数は現在の検索結果の件数です。ステータスを指定しても3列は残ります。
- 再取得は、最後に検索した条件でAPIを再実行します。未送信の入力は検索ボタンで適用してください。
- APIが停止しているとエラーを表示します。起動後に「もう一度取得」で復帰できます。
- 日付は `YYYY/MM/DD`、期限未設定は「期限なし」です。未着手・作業中で今日より前の期限を強調します。

デモと同じ位置に「＋ タスクを追加」、各列の優先度・期限の昇順／降順ボタンを配置しています。カード選択で詳細を表示します。並べ替えは表示中の画面にのみ反映し、再読み込みで解除されます。追加モーダルもデモに合わせて配置していますが、登録・編集・削除は準備中として無効化しています。カード移動と並べ替えの永続化は後続実装です。デモのlocalStorageは読み書きしません。狭い画面でも3列を維持し、ボード領域を横スクロールします。

## テスト・ビルド

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

VitestとTesting Libraryによる自動テストは架空のレスポンスを使用し、DBの起動は不要です。検索条件の組み立て、3列・カード・件数・期限、0件、通信エラーからの再取得、古い応答の無視、タイムアウト、React StrictModeでの再実行を検証します。

ビルド結果は `dist/` に生成します。`npm run preview` はビルドした静的画面を確認するためのものです。APIプロキシは開発サーバーのみに設定しているため、API連携の確認には `npm run dev` を使用してください。外部公開・デプロイの設定は含みません。リポジトリの削除禁止方針に合わせ、ビルドは既存の `dist/` を空にしません。

## 確認結果（2026年11月16日）

- 元の作業場所への移動と画面修正後、自動テスト41件成功。型チェック・Lint・ビルド成功。
- ローカルPostgreSQLとSpring BootのヘルスチェックがUP。
- Vite経由の実APIで4件取得。既存の架空データを使用し、新しいDBデータは投入していません。
- Chromeで3列の表示と配色を確認。全件4件、`API × 作業中`の1件、該当なし0件、クリア後4件への復帰を確認。
- 通信失敗・10秒タイムアウト・古い応答による上書き防止は自動テストで確認。
- 3列×4種類の並べ替え、他の列への影響なし、同順位の直前順維持、期限なしは最後、取得中・失敗時の無効化を自動テストで確認。
- 検索欄の開閉、2か所のクリア、再取得、追加・詳細モーダル、キャンセル・閉じる・cancelイベント、フォーカス復帰、未実装操作の無効化を自動テストで確認。
- jsdomのテストではdialogの開閉APIのみ補っています。実ブラウザでのTab循環・Escapeキーの一連の操作、狭い画面での目視、別端末・別ブラウザは未確認です。

## 構成

| ファイル | 役割 |
|---|---|
| `src/main.tsx` | Reactとルーティングの入口 |
| `src/App.tsx` | 検索フォーム、適用条件、取得状態の表示 |
| `src/api/tasks.ts` | URLの組み立て、Fetch、HTTP・データ形式の確認 |
| `src/hooks/useTasks.ts` | 読み込み・結果・失敗の状態と通信中断 |
| `src/components/TaskBoard.tsx` | 取得したタスクを進捗別に表示 |
| `src/components/TaskCard.tsx` | 1件のタイトル・優先度・期限を表示 |
| `src/types.ts` | APIレスポンスと条件のTypeScript型 |
| `vite.config.ts` | 開発サーバー・API転送・テスト設定 |

仕組みは[実装のポイント](実装のポイント.md)で解説しています。使用技術の公式資料：[Vite](https://vite.dev/guide/)、[Tailwind CSS](https://tailwindcss.com/docs/installation/using-vite)、[React Router](https://reactrouter.com/start/declarative/installation)、[Vitest](https://vitest.dev/guide/)。

## デモに合わせた画面修正

大きな検索フォームをボード上部から下部の折りたたみへ移動し、デモのヘッダー・追加ボタン・件数・取得状態・列内ソート・カード・モーダルの配置とCSS寸法へ合わせました。PROTOTYPE表記とデモ専用の確認メニューは実アプリへ含めていません。APIのデータとデモのlocalStorageのデータは別なので、カードの件数や内容は異なります。

画面修正直後は利用者の指示によりテストを省略していました。その後のテスト依頼に従い、元の作業場所へ移動してから操作テストを追加・実行し、上記の41件と型チェック・Lint・ビルドを確認しました。並べ替え切り替え時の同順位の維持と、モーダル描画後のフォーカス処理も修正しています。
