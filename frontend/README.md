# Task Board フロントエンド

既存のタスクREAD APIからデータを取得し、未着手・作業中・完了の3列に表示するReactアプリです。合意済みの[プロトタイプ](../prototype/index.html)のレイアウト・配色を引き継いでいます。

## 必要な環境

- Node.js: `^22.22.2 || ^24.15.0 || >=26.0.0`（使用するテストツールを含む依存関係の要件）
- 検証環境: Node.js 26.7.0 / npm 11.19.0。`.node-version`にも記載しています。
- PostgreSQLとSpring Bootの起動環境は[バックエンドREADME](../backend/README.md)を参照してください。

## 使用バージョン

React / React DOMは19.3.1、TypeScriptは6.0.3に固定しています。2026年11月17日に確認したTypeScript最新安定版は7.0.2ですが、最新typescript-eslint 8.72.2も対応範囲が`>=4.8.4 <6.1.0`のため、今回は更新しません。ほかの技術も含めた採用・維持理由と更新方針は[技術構成書](../技術構成書.md)の1.1・1.2節を参照してください。

## ローカルで起動する

1. 元のプロジェクトディレクトリで、既存のREADMEに従ってDBとバックエンドを起動してください。バックエンドは通常 `http://127.0.0.1:8080` です。フロントエンドには `.env` やDBパスワードは不要です。
2. 元のプロジェクトディレクトリの `frontend/` で実行します。追加ワークツリーは使用しません。

```sh
npm ci --ignore-scripts --no-audit --no-fund
TASK_API_TARGET=http://127.0.0.1:8080 npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

3. Chromeで `http://127.0.0.1:5173/` を開きます。

`npm ci`は依存関係をlockファイルどおりにそろえるコマンドです。すでに必要な依存関係がある環境では再実行は不要です。起動中の開発サーバーはCtrl+Cで停止します。5173が使用中の場合は自動で別ポートに切り替えずエラーになります。

標準ポートはフロント5173・バックエンド8080・DB5432に固定します。競合時は別ポートへ変更せず、起動元を確認して競合サービスを通常停止してから起動します。同じプロジェクトが正常起動済みなら再利用します。詳しくは[統一起動スキル](../skills/start-frontend-backend/SKILL.md)を参照してください。

DBが空ならボードも空です。必要ならバックエンドREADMEのローカル専用の架空データ投入手順を使用してください。通常起動ではサンプルを自動投入しません。

## 操作

- 初回表示は全件取得です。
- ボード下の「タスクを検索」を開き、「タイトルを検索」と「ステータス」を入力します。検索ボタンまたはEnterで検索します。入力途中では検索しません。
- タイトルは部分一致で検索し、大文字小文字を区別しません。説明文は検索対象外です。
- ステータスとタイトルを両方指定すると両条件に一致するタスクを表示します。
- クリアで入力と適用条件をリセットし、全件を取得します。
- 件数は現在の検索結果の件数です。ステータスを指定しても3列は残ります。
- 列ごとのソートは検索・再取得後も適用されますが、画面の再読み込みで解除されます。同順位は編集・再取得の直前に表示していた順序を保ちます。
- 再取得は、最後に検索した条件でAPIを再実行します。未送信の入力は検索ボタンで適用してください。
- APIが停止しているとエラーを表示します。起動後に「もう一度取得」で復帰できます。
- 日付は `YYYY/MM/DD`、期限未設定は「期限なし」です。未着手・作業中で今日より前の期限を強調します。

デモと同じ位置に「＋ タスクを追加」、各列の優先度・期限の昇順／降順ボタンを配置しています。カード選択で、一覧APIから取得済みのデータを詳細表示します（詳細APIへの再通信は行いません）。並べ替えは表示中の画面にのみ反映し、再読み込みで解除されます。追加モーダルもデモに合わせて配置していますが、登録はPOST APIで保存し、編集とカード移動・手動順序の保存に対応しています。削除確認と物理削除にも対応しています。削除確認省略設定はDBに保存します。ソート条件は画面内のみ保持し、永続化は行いません。デモのlocalStorageは読み書きしません。狭い画面でも3列を維持し、ボード領域を横スクロールします。

## テスト・ビルド

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

VitestとTesting Libraryによる自動テストは架空のレスポンスを使用し、DBの起動は不要です。検索条件の組み立て、3列・カード・件数・期限、0件、通信エラーからの再取得、古い応答の無視、タイムアウト、React StrictModeでの再実行を検証します。

ビルド結果は `dist/` に生成します。`npm run preview` はビルドした静的画面を確認するためのものです。APIプロキシは開発サーバーのみに設定しているため、API連携の確認には `npm run dev` を使用してください。外部公開・デプロイの設定は含みません。リポジトリの削除禁止方針に合わせ、ビルドは既存の `dist/` を空にしません。

## デモに合わせた画面修正

大きな検索フォームをボード上部から下部の折りたたみへ移動し、デモのヘッダー・追加ボタン・件数・取得状態・列内ソート・カード・モーダルの配置とCSS寸法へ合わせました。PROTOTYPE表記とデモ専用の確認メニューは実アプリへ含めていません。APIのデータとデモのlocalStorageのデータは別なので、カードの件数や内容は異なります。


## タスクの新規登録

追加フォームからPOST /api/tasksへJSONを送り、保存成功時に閉じて一覧を再取得します。新規タスクは未着手、既定の優先度は中、説明・期限は任意です。タイトルは空白を除いて1〜255文字です。送信中は二重送信と閉じる操作を抑止し、失敗時は入力を維持します。通信結果が不明な場合は、再取得で追加済みでないことを確認してから再試行してください。

登録成功時は検索条件を解除し、追加したタスクを確認できる全件表示へ戻します。選択中の列ソートはその画面内で維持します。再読み込み後はDBに保存されたsortOrderの順で表示します。優先度・期限ボタンのソート条件は保存しません。


## タスクの編集・移動

カードの詳細から「編集する」でタイトル・説明・優先度・期限を変更できます。PUT /api/tasks/{id}で保存し、成功時は更新した詳細へ戻ります。キャンセル・閉じる・Escapeは変更を保存せず詳細へ戻り、保存失敗時は入力を保持します。編集で進捗・順序は変更しません。

全件表示のボードでは、カードを他の列やカードの上半分・下半分にドラッグして進捗と列内順序を保存できます。PATCH /api/tasks/{id}/positionへstatusとbeforeId（末尾ならnull）を送ります。移動成功後だけボードを再取得し、移動元・移動先の画面内ソートを解除します。失敗時は元の表示・ソートを維持します。検索による絞り込み中は、非表示タスクとの誤った順序変更を避けるためドラッグを無効にします。検索条件をクリアすると移動できます。

再読み込みで編集内容・進捗・手動順序を復元します。優先度・期限のソート条件の永続化は不要と決定し、実装しません。

## 同時編集時の制限

複数の画面で同じタスクを編集した場合、古い画面からの保存を競合として検出する仕組みはありません。後から適用された編集が上書きするため、現在は単一利用者・単一ボードを前提とします。設計上の制約は[技術構成書 第7章](../技術構成書.md#7-現在の実装上の制約と見直す条件)で管理します。

## タスクの削除

詳細の「削除」で確認画面を開きます。対象タイトルと元に戻せない旨を確認し、「削除する」でDELETE /api/tasks/{id}を送ります。DBのレコードを物理削除するため、復元機能はありません。初期状態では確認を表示します。「今後この確認を表示しない」を選んで削除が成功すると、以後は詳細の「削除」から直ちに削除を要求します。確認省略設定もDBに保存するため、再読み込み後も保持します。

チェックの変更だけでは設定を保存しません。キャンセル・閉じる・Escapeでは詳細へ戻り、タスクも設定も変更しません。確認時はキャンセルへフォーカスを置き、送信中は二重送信と閉じる操作を抑止します。204成功後にモーダルを閉じ、追加ボタンへフォーカスを戻し、適用済みの検索条件と画面内ソートを保ったまま一覧を再取得します。削除により空になった列は空表示になります。

削除確認の送信失敗時は対象・チェック・確認画面を保持してエラーを表示します。確認省略中の失敗では詳細画面を保持します。404や通信断・15秒のタイムアウトなどで結果不明の場合は、確認画面があればキャンセルしてから詳細を閉じ、再取得で実際の状態を確認してください。削除成功後の一覧取得だけが失敗した場合は、削除成功の通知と取得エラーを別々に表示します。

削除ボタンを押すと `GET /api/settings` で最新設定を取得します。取得中は編集・閉じる・再送を抑止し、取得できない場合は削除せず詳細にエラーを表示します。チェックありの確定は `DELETE /api/tasks/{id}?skipConfirmation=true` で、タスク削除と設定変更を一括保存します。チェックなし・確認省略中はクエリなしで削除し、保存済み設定を変えません。通信断ではサーバー側で保存済みの可能性があるため、再取得で状態を確認してください。

削除確認を再び有効にする操作は現在の実アプリには設けていません。デモ専用の再有効化メニューは移植していません。

## 起動時の表示と画面が開かない場合

Reactが起動するまで、HTMLに含めた「画面を読み込み中です」を表示します。起動後はボードへ置き換わります。JavaScriptが無効な場合は、有効化を案内します。この初期表示は、起動後のJavaScript例外を捕捉するものではありません。

表示が戻らない場合は、次を順に確認します。

1. 画面のURLが `http://127.0.0.1:5173/` であること、フロントの開発サーバーが標準ポートで起動していること。
2. Chromeの開発者ツールでConsoleの実行時エラーと、NetworkのHTML・JavaScript・CSSの取得失敗を確認すること。共有時は認証情報やタスク本文を除くこと。
3. ボードは開くがタスク取得エラーになる場合は、バックエンドの起動状態と `http://127.0.0.1:8080/actuator/health` を確認すること。

HTMLの200応答やビルド成功だけで画面の正常性を判断せず、再読み込み後のボード表示と操作まで確認します。

## 静的品質チェック

`npm run lint` でESLintのTypeScript/React Hooksルールを検査します。`npm run build` は型検査を含むため、同一状態で別途typecheckを重複実行する必要はありません。
