# フロント・バックエンド起動

このプロジェクトを元の作業場所で起動し、画面からAPIまで接続できる状態にする。ワークツリーは作成・利用しない。

## 標準ポートと許可範囲

| サービス | 固定する待ち受け先 |
|---|---|
| フロントエンド | `127.0.0.1:5173` |
| バックエンド | `127.0.0.1:8080` |
| PostgreSQLのホスト側 | `127.0.0.1:5432` |

- 別ポートへの自動切り替え、`8081`などへの逃避、`.env`・ソース・起動引数によるポート変更を回避策にしない。ViteのstrictPortを維持する。`4173`のpreviewを通常起動の代用にしない。
- このプロジェクトの起動依頼には、上記ポートと競合する他プロジェクトのローカル開発サービスを特定して停止することについて、利用者から継続的な許可がある。同じ停止の許可を毎回聞き直さず、環境の承認要件には従う。競合しないサービスは停止しない。
- このプロジェクトが正常起動済みなら再利用し、二重起動しない。起動元がこのプロジェクトでも不健康な場合は必要なサービスだけ再起動する。
- 停止はデータを保持する通常終了に限る。強制終了・広範囲なプロセス停止・コンテナやボリューム削除は行わない。今回の許可は、他プロジェクトのファイル編集・未保存作業の破棄・リモートサービス停止・セキュリティ設定変更を含まない。
- 所有元が不明、通常停止できない、停止後も自動復帰する原因を特定できない場合は、原因と対象ポートを報告して中断する。別ポートでは起動しない。

## 1. プロジェクトと前提を確認

現在の作業場所がRaiseTech_TaskManagerリポジトリであることを確認し、`git rev-parse --show-toplevel` でルートを特定する。そのディレクトリの `AGENTS.md`、`frontend/README.md`、`backend/README.md` を確認する。別プロジェクトで呼び出された場合は対象リポジトリの正規の場所を確認してから移動し、複製やworktreeを作らない。

起動前に `git status --short --branch`、Node/npm、Docker、Java 25、依存関係とローカル設定の存在を確認する。起動だけの依頼ではソースを編集せず、新規Issue・ブランチ・コミット・pushを作らない。

- Dockerエンジンが停止していればDocker Desktopを起動する。
- `.env` がなければルートで `sh scripts/setup-local-db.sh` を使う。既存ファイルを上書きせず、内容や認証情報を表示しない。
- `frontend/node_modules` がなければ、frontendで `npm ci --ignore-scripts --no-audit --no-fund` を実行する。インストール済みなら毎回やり直さない。
- この端末のJDKは `backend/.local/jdk-25.0.5+8/Contents/Home`。存在・バージョンを確認する。存在しなければ利用可能なJava 25を確認し、なければ不足を報告する。
- 起動できる前提を確認してから競合サービスを停止し、停止後に準備不足が判明して待たせることを避ける。

## 2. ポートの使用元を確認して競合だけを解消

```sh
lsof -nP -iTCP:5173 -sTCP:LISTEN
lsof -nP -iTCP:8080 -sTCP:LISTEN
lsof -nP -iTCP:5432 -sTCP:LISTEN
```

リスナーなしの終了コード1は空きポートとして扱う。localhost限定の競合だけでなく、`*`や`0.0.0.0`など同じポートを占有するローカルリスナーも確認する。

1. 表示されたPIDについて、実行名、親PID、作業ディレクトリ、プロセスの開始時刻を必要な範囲で調べる。`ps`は`pid,ppid,comm,lstart`、`lsof`は`cwd`など必要な項目に絞り、コマンド引数や環境変数を一括出力しない。起動元のプロジェクトを確認し、サービス名だけで同一プロジェクトと判断しない。
2. Docker経由のポートなら `docker ps --format '{{.ID}}\t{{.Names}}\t{{.Ports}}'` で対象コンテナを特定する。必要なら対象のComposeプロジェクト・service・working_dirラベルのみを確認する。`docker inspect`全体や`docker compose config`は認証情報を含み得るため表示しない。
3. 他プロジェクトと確認できたら、対象ポート・サービス・起動元と停止する旨を短く伝え、通常停止を実行する。コンテナは確認したコンテナIDへの `docker stop`、起動した端末を管理できる場合はCtrl+C、直接プロセスなら確認したPIDへのSIGTERMを使う。Homebrewなど管理サービスの場合は確認したサービスだけを管理コマンドで停止する。Dockerのホスト側プロセスをkillしてDocker全体を落とさない。
4. 停止の直前に同じPID・開始時刻・ポートであることを再確認し、PIDの再利用による誤停止を防ぐ。`kill -9`、`killall`、`pkill node/java`、PIDを調べず一括killする処理は使わない。
5. 停止後は最大20秒程度の短い区切りで解放を確認する。監視プロセスが再起動する場合は親の起動管理を特定して対象サービスだけを通常停止する。それでも停止できなければ中断する。

同じプロジェクトの正常な既存サービスは再利用する。DBはポートが開いているだけで再利用せず、このComposeのdbであることとhealthy状態を確認する。バックエンドは起動元とヘルスチェック、フロントは起動元とHTTP応答を確認する。

## 3. DB → API → フロントの順で起動

停止しているサービスだけを起動する。以下はそれぞれ指定ディレクトリで実行する。環境変数で標準ポートを明示し、過去の設定による別ポート起動を避ける。

プロジェクトのルート：

```sh
DB_PORT=5432 docker compose up -d --wait db
docker compose ps db
```

backend：

```sh
export JAVA_HOME="$PWD/.local/jdk-25.0.5+8/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
DB_HOST=127.0.0.1 DB_PORT=5432 SERVER_PORT=8080 GRADLE_USER_HOME=/private/tmp/taskmanager-gradle ./gradlew bootRun --args='--server.address=127.0.0.1 --server.port=8080'
```

frontend（バックエンドとは別の管理可能な実行セッション）：

```sh
TASK_API_TARGET=http://127.0.0.1:8080 npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

JavaとViteはそれぞれ保持できる実行セッションで動かし、PIDまたはセッションIDと作業ディレクトリを把握する。全環境変数を表示せず、`.env`の認証情報をフロントへ渡さない。標準ポートでの起動に失敗したら、競合・設定・依存サービスを調べる。別ポートに変えて成功扱いしない。

## 4. 完了の確認と報告

バックエンドのヘルスチェックがUPになってからフロントを確認する。待機は20秒程度の区切りで進捗を伝え、2分程度を目安に解消しない失敗は原因とともに報告する。

```sh
curl --fail --silent --max-time 5 http://127.0.0.1:8080/actuator/health
curl --fail --silent --max-time 5 --output /dev/null http://127.0.0.1:8080/api/tasks
curl --fail --silent --max-time 5 --output /dev/null http://127.0.0.1:5173/
curl --fail --silent --max-time 5 --output /dev/null http://127.0.0.1:5173/api/tasks
```

実際のリスナーが5173・8080・5432であることも確認する。APIレスポンス本文や業務データは不用意に表示しない。データ0件でも正常とし、起動のためにサンプルを投入しない。起動依頼だけなら毎回フルテストを実行する必要はない。

ブラウザ確認が可能なら5173の画面を開き、一覧・検索とAPIエラーの有無を確認する。ブラウザ操作が使えない場合はHTTP確認と未確認範囲を明記する。

最終報告には画面URL、API URL、各サービスの起動・再利用状態、停止した競合サービス、起動失敗や未確認事項を記載する。停止した別プロジェクトは自動で再起動せず、必要なら再開手段を伝える。単なる起動依頼では、このプロジェクトを起動した状態で引き渡す。
